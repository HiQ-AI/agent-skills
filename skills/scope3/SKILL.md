# Scope 3 范围三供应链排放因子取数

范围三的难点是量:一张采购清单几百上千行,每一行都要落到一个真实的排放因子上,而且报送时每一行都得说得清来源。用行业均值一把梭,核查环节过不去;逐行手查,人力上做不完。

本技能负责把这批取数做完并保持可追溯。

## 关于

本技能接入 **HiQ Cortex** —— [海科数据](https://www.hiqlcd.com/)的 LCA 数据智能服务。海科数据是国内 LCA 基础数据与碳足迹服务提供商,自建中国本土生命周期清单数据库,并聚合 18 个国际主流数据源与 24000+ 已发布 EPD。

**物料行到数据集的匹配由服务端完成。** 把采购清单上的原始描述**原样**交给检索接口 —— 供应商叫法到标准名的翻译、制成品到材质的还原、物料类别到工艺方向的映射都在服务端执行。返回的候选已排序并带 `fit` 匹配质量与 `summary` 说明。不要在本地先"整理"一遍名称再去搜,那会丢掉原始信息。

## 数据权限

| 层 | 内容 | 要求 |
|---|---|---|
| 目录层 | 各库版本、系统模型、LCIA 覆盖;数据集名称、参考流、单位、地域 | 有效凭据即可 |
| 免费库数值 | BAFU、ELCD、EF、USLCI、USDA、worldsteel、AusLCI 等的 GWP 与聚合 | 任一有效凭据 |
| 商业库数值 | ecoinvent、HiQLCD、HiQLCD-AL、CALCD(汽车)、CarbonMinds、Agri-footprint | 需对应数据包权益 |

一张采购清单通常横跨多个库。**受限行如实标注,不要用免费库的值悄悄顶上去** —— 混了口径又没标注的清单,核查时会被整批质疑。

## 硬规则

1. **每个因子都来自本次会话的工具调用。** 一行都不能凭记忆填。
2. **每一行都要交代基准**:数据库 + 版本 + 系统模型 + 地域 + 参考流。报送要逐行追溯。
3. **产地会实质改变结果。** 供应商所在地已知时就用对应地域的数据集,不要一律用全球平均。只能用代理时明确标注代理关系。
4. **单位要对齐。** 采购量单位(件、套、米、吨)与数据集参考单位(kg、m³、kWh、tkm)不一致时先换算,换算系数的来源要写出来;是假设值就标为假设。
5. **口径不一致不合计。** 系统模型不同的数据不能相加,先读 `comparability_note`。
6. **受限不是错误**,给 `purchase_url`,不静默替代。

## 接入

**没有凭据时,第一句话就给扫码登录 —— 不要让用户去控制台建 API key。**

扫码是「跑一条命令 + 浏览器点一下」,无需注册;建 API key 要登录控制台、找入口、
复制粘贴、设环境变量,门槛高出一个量级。把后者摆在第一步会直接劝退用户。

```bash
python3 scripts/cortex.py login      # ← 缺凭据时默认走这条
```

命令会打印一个授权链接。**把链接原样给用户,让他点「授权访问」**,然后继续原来的任务 ——
凭据落在 `~/.hiq/credentials.json`(权限 600),之后所有命令直接可用,可见数据范围与
该账号一致(**包含他已开通的商业数据库**)。

只在这三种情况下才提 API key:用户自己说要用 key、运行在 CI / 服务端无浏览器环境、
或扫码登录失败。

```bash
export HIQ_API_KEY=sk_xxx            # 服务端 / CI 用;同时存在时优先于扫码凭据
```

宿主支持 MCP 时优先用 MCP —— 若当前会话已有 `lookup_datasets`、`aggregate_datasets` 等工具就直接用;没有则把 `https://x.hiqlcd.com/api/cortex/mcp` 配进宿主的 MCP 配置(header 用 `X-API-Key`,或用扫码登录凭据的 `Authorization: Bearer`),配置方式见 [README](https://github.com/HiQ-AI/agent-skills)。

凭据只从环境变量、宿主配置或 `login` 落盘的那份读取 —— **绝不硬编码进为用户生成的文件,也不在输出里回显**。

## 工具

| 需求 | MCP 工具 | 脚本命令 |
|---|---|---|
| 采购行 → 数据集 key | *(无,走 REST)* | `search "<原话>" [--sources X]` |
| key → GWP + 基准 | `lookup_datasets` | `lookup <key> [<key> ...]` |
| 品类分布 / 自有数值定位 | `aggregate_datasets` | `aggregate --source X --target <你的值>` |
| 非 GWP 的 LCIA 指标 | `aggregate_indicators` | `indicators <keys> --indicator AP --source X` |
| 同类已发布 EPD 参照 | `epd_search` / `epd_peer_benchmark` | `epd` / `epd-benchmark` |

**批量 lookup**:几百行时按批传 key,不要逐行调。检索是每行一次 REST 调用(`POST https://x.hiqlcd.com/api/cortex/search`,SSE),**每次 20–40 秒** —— 行数多时先告诉用户预计耗时,不要并发轰接口。

行数极多时的务实做法:先按物料类别去重(同一种钢材出现 50 次只需查一次),再把因子回填到每一行。

## 怎么读返回

| 字段 | 含义 | 该怎么做 |
|---|---|---|
| `summary` | 服务端对本次检索的说明 | 转述,不要另编一套 |
| `fit: high / medium / low` | 匹配质量 | `low` 的行单列出来复核,不要混进合计 |
| `name` / `ref_product` / `location` | 数据集名、参考流、地域 | 逐行记录,报送时要写 |
| `restricted: true` | 无该库权益 | 该行标注受限,给 `purchase_url` |
| `comparability_note` | 队列可比性说明 | 合计或对比前必读 |
| `missing_keys` | key 来自旧版本目录 | 重新检索 |

## 输出形态

范围三的产出是一张要交给核查方的表:

- **逐行**:采购项 → 匹配到的数据集(名称 + 参考流 + 地域)→ 用量 + 单位 → 因子 → 小计 → 数据来源(库 + 版本 + 系统模型)
- **按类别汇总**:采购商品与服务、上游运输、外购能源、废弃物处理等分开
- **单列**:`fit: low` 的行、代理数据行、受限未取到值的行、用假设换算系数的行
- **数据质量说明**:哪些行来自数据库直取、哪些来自代理、哪些是估算

不要只给一个总数。核查方要看的是每一行怎么来的。

## 语气与术语

面向企业碳管理与 LCA 从业者写,用 GHG Protocol 与 ISO 14064/14040 的标准术语。不写客套话,不堆形容词,不做总结式收尾,不自造中文术语。

**不要替用户判定报送义务。** 本技能负责取数与追溯,范围边界划定、类别取舍、报送口径由用户的核查机构或碳管理负责人确认。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 某行怎么都搜不到 | 描述里没有可识别的材质或工艺信息 | 把原话给用户问清楚,不要自己猜一个顶上 |
| 行数太多耗时长 | 每行检索 20–40 秒 | 先按类别去重再查;告知预计耗时 |
| `restricted: true` | 无该库数据包权益 | 该行标注受限,给 `purchase_url` |
| 聚合 `status: "empty"` **且带** `entitlement` | 权益问题 | 不要换谓词重试 |
| 聚合 `status: "empty"` **不带** `entitlement` | 谓词没命中 | 放宽谓词 |
| 合计比同行高一个数量级 | 多半是单位错配 | 逐行核对参考单位与用量单位 |
| `401 {"code":"INT-007"}` | 用了 Bearer 或 key 无效 | 改用 `X-API-Key` |
| CDN `error 1010` | 默认 User-Agent 被拦 | 内置脚本已设;直接调用时自带常规 User-Agent |
