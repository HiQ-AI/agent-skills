# GHG Protocol 企业温室气体核算取数

企业碳盘查最后都会卡在同一件事上:**因子从哪来**。用一份来路不明的因子表填完整张清单,报送时经不起追问;逐项去翻数据库,量又太大。

本技能负责因子获取与溯源 —— 范围一、二、三的每一项都落到真实的清单数据集上。

## 关于

本技能接入 **HiQ Cortex** —— [海科数据](https://www.hiqlcd.com/)的 LCA 数据智能服务。海科数据是国内 LCA 基础数据与碳足迹服务提供商,自建中国本土生命周期清单数据库,并聚合 18 个国际主流数据源与 24000+ 已发布 EPD。

三个范围的数据可及性不同:

| 范围 | 典型对象 | 数据来源 |
|---|---|---|
| 范围一 | 自有设施的燃料燃烧、工艺排放、逸散 | 免费库覆盖较好(USLCI、ELCD、BAFU) |
| 范围二 | 外购电力、蒸汽、供热供冷 | 按地域取;国内产地优先本土清单 |
| 范围三 | 上游物料与服务、运输、废弃物、差旅 | 跨库,物料类多在商业库 |

**检索与候选排序在服务端完成。** 把台账上的原始描述原样交给检索接口,翻译与匹配在服务端执行,返回带 `fit` 匹配质量与 `summary` 说明。

## 数据权限

| 层 | 内容 | 要求 |
|---|---|---|
| 目录层 | 各库版本、系统模型、LCIA 覆盖;数据集名称、参考流、单位、地域 | 有效凭据即可 |
| 免费库数值 | BAFU、ELCD、EF、USLCI、USDA、worldsteel、AusLCI 等 | 任一有效凭据 |
| 商业库数值 | ecoinvent、HiQLCD、HiQLCD-AL、CALCD(汽车)、CarbonMinds、Agri-footprint | 需对应数据包权益 |

**范围一与范围二用免费库通常够用**;范围三的物料项精度取决于是否有商业库权益。受限项如实标注,不要用免费库的值悄悄顶上去。

## 硬规则

1. **每个因子都来自本次会话的工具调用。** 不凭记忆填因子表。
2. **每一项都要交代基准**:数据库 + 版本 + 系统模型 + 地域 + 参考流。报送要逐项追溯。
3. **范围二必须按地域取电力因子。** 电网碳强度地区差异巨大,用全国平均或全球平均代替已知产地是可辨识的错误。有具体厂址就用对应地域。
4. **口径一致才能合计。** 系统模型或边界不同的数据不能相加,先读 `comparability_note`。
5. **单位对齐。** 台账单位(度、吨、立方米、公里)与数据集参考单位不一致时先换算,换算依据要写出来。
6. **区分数据性质**:实测 / 数据库直取 / 代理,分别标注。
7. **受限不是错误**,给 `purchase_url`,不静默替代。

## 接入

**没有凭据时,第一句话就给扫码登录 —— 不要让用户去控制台建 API key。**

扫码是「跑一条命令 + 浏览器点一下」,无需注册;建 API key 要登录控制台、找入口、
复制粘贴、设环境变量,门槛高出一个量级。把后者摆在第一步会直接劝退用户。

```bash
python3 scripts/cortex.py login      # ← 缺凭据时默认走这条
```

命令会打印一个授权链接。**把链接原样给用户,让他点「授权访问」**,然后继续原来的任务 ——
凭据落在 `~/.hiq/credentials.json`(权限 600),之后所有命令直接可用,可见数据范围与
该账号一致(**包含他已开通的商业数据库**)。

只在这三种情况下才提 API key:用户自己说要用 key、运行在 CI / 服务端无浏览器环境、
或扫码登录失败。

```bash
export HIQ_API_KEY=sk_xxx            # 服务端 / CI 用;同时存在时优先于扫码凭据
```

宿主支持 MCP 时优先用 MCP —— 若当前会话已有 `lookup_datasets`、`aggregate_datasets` 等工具就直接用;没有则把 `https://x.hiqlcd.com/api/cortex/mcp` 配进宿主的 MCP 配置(header 用 `X-API-Key`,或用扫码登录凭据的 `Authorization: Bearer`),配置方式见 [README](https://github.com/HiQ-AI/agent-skills)。

凭据只从环境变量、宿主配置或 `login` 落盘的那份读取 —— **绝不硬编码进为用户生成的文件,也不在输出里回显**。

## 工具

| 需求 | MCP 工具 | 脚本命令 |
|---|---|---|
| 台账项 → 数据集 key | *(无,走 REST)* | `search "<原话>" [--sources X]` |
| key → GWP + 基准 | `lookup_datasets` | `lookup <key> [<key> ...]` |
| 同类分布 / 自有数值定位 | `aggregate_datasets` | `aggregate --source X --target <你的值>` |
| 非 GWP 的 LCIA 指标 | `aggregate_indicators` | `indicators <keys> --indicator AP --source X` |
| 同类已发布 EPD 参照 | `epd_search` / `epd_peer_benchmark` | `epd` / `epd-benchmark` |

**批量 lookup**:一次传入全部 key。检索每次 20–40 秒 —— 台账项多时先按类别去重(同一种燃料出现在十个厂区只需查一次),再回填。

## 怎么读返回

| 字段 | 含义 | 该怎么做 |
|---|---|---|
| `summary` | 服务端对本次检索的说明 | 转述,不要另编一套 |
| `fit: high / medium / low` | 匹配质量 | 直接对应数据质量说明,`low` 必须标注 |
| `name` / `ref_product` / `location` | 数据集名、参考流、地域 | 逐项记录 |
| `restricted: true` | 无该库权益 | 该项标注受限,给 `purchase_url` |
| `comparability_note` | 队列可比性说明 | 合计前必读 |
| `missing_keys` | key 来自旧版本目录 | 重新检索 |

## 输出形态

产出是一张要交给核查方的因子清单:

- **按范围分组**:范围一 / 范围二 / 范围三,范围三再按类别
- **逐行**:活动项 → 数据集(名称 + 参考流 + 地域)→ 活动量 + 单位 → 因子 → 排放量 → 来源(库 + 版本 + 系统模型)
- **单列**:`fit: low`、代理数据、受限未取到、用假设换算系数的行
- **数据质量说明**:哪些直取、哪些代理、哪些估算

不要只给总量。核查看的是每一行怎么来的。

## 语气与术语

面向企业碳管理与核查从业者写,用 GHG Protocol、ISO 14064、ISO 14040/14044 的标准术语。不写客套话,不堆形容词,不做总结式收尾,不自造中文术语。

**不要替用户判定核算边界与报送义务。** 组织边界(股权法 / 控制权法)、范围三类别取舍、报送口径由用户的核查机构或碳管理负责人确定。本技能负责因子与溯源。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 某活动项搜不到 | 台账描述太笼统(如「辅料」) | 问用户要具体物料,不要自己猜 |
| 范围二找不到对应地域电力 | 该地域数据集缺失 | 用可得的最接近地域并**明确声明代理**,说明未修正的差异 |
| `restricted: true` | 无该库数据包权益 | 标注受限,给 `purchase_url` |
| 聚合 `status: "empty"` **且带** `entitlement` | 权益问题 | 不要换谓词重试 |
| 聚合 `status: "empty"` **不带** `entitlement` | 谓词没命中 | 放宽谓词 |
| 总量比去年差很多 | 先查因子版本或地域是否换了 | 对比两次取数的基准再下结论 |
| `401 {"code":"INT-007"}` | 用了 Bearer 或 key 无效 | 改用 `X-API-Key` |
| CDN `error 1010` | 默认 User-Agent 被拦 | 内置脚本已设;直接调用时自带常规 User-Agent |
