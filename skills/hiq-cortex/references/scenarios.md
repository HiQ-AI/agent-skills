# 场景方法:行业对标与轻量估算

两类请求不走「检索 → 取值」的主流程,方法不同,交付物也不同。

## 一、行业对标(用户有自己的数值)

触发:「我这个 X kgCO₂e/kg 算高还是低」「比同行如何」「行业平均是多少」「在行业里什么水平」。

用户要的不是某一条数据集的值,而是**一个分布里的位置**。用 `aggregate_datasets`(脚本 `aggregate`)。

### 步骤

1. **把产品收敛成一个可比队列。** 只能同类比同类,先定这几个维度:材料/产品族、地域、**功能单位**(每 kg?每 m³?每件?)、系统模型(截止法 / APOS / 后果法)。有歧义就问一两个问题,别猜。

2. **用谓词而不是手挑 key。** 要的是「行业」这个总体,不是三十条样本:
   ```
   aggregate --source hiqlcd --category steel --target 2.5
   ```
   只有当用户明确点名了少数几条数据集时,才用 `--keys`。

3. **先读返回里的自述再开口。** 结果带 `count`、`cohort_profile.by_source`、`comparability_note`、`percentiles`。

4. **可比性不过关就降级,不要硬给百分位。** 在口径混杂的队列上自信地说「你比平均低 15%」,比不回答更糟:
   - **单位混杂**(kg / MJ / 件)→ 不可直接比。锁定一个功能单位重查,或如实说明。
   - **系统模型混杂**,或 **n < 8** → 降级为量级参考(「同类偏少,量级上看…」),不给精确分位。
   - 用户自己的**系统边界**(到大门 / 到坟墓,是否含运输与末端)可能与队列不同 —— 主动指出。

5. **诚实定位。** 给出百分位 + 相对百分比 + 队列基准,并说明**样本量**和**来自哪些库**:

   > 在 HiQLCD 钢铁队列(n=21614,cut_off,功能单位 1 kg)里,你处于约 P20,比行业中位低约 29%,属偏低。若你的边界含运输或末端,对比基准需相应上调。

**碳是越低越好** —— 判断「好/差」看 `target` 里相对中位数的符号,不要一律说成利好。P71 的产品其实差于中位。

### 禁止

- 不要凭记忆编「行业平均」,必须来自聚合结果。
- 不要在单位或系统模型混杂时不加说明就给定位。
- 不要拿一小撮检索样本当行业总体。
- **不要把队列收窄到只剩一条来读出某个受限数据集的值。** 聚合接口是给分布用的,单条数值走 `lookup` 并受权益约束 —— 用聚合绕过授权是滥用。

## 二、轻量估算(还没有 BOM)

触发:「产品碳排大概什么量级」「几个材料方案选哪个,碳上差多少」。

用户数据不完整,但现在就需要一个有意义的方向,而不是等数据齐了再说。

**不属于这个场景**:已有真实 BOM → 走主流程的匹配;用户已有自己的数值问高低 → 走上面的对标。

### 输入 —— 问几个关键的,别索要完整 BOM

- 产品类型 / 功能
- 主要材料及大致占比(不需要精确质量)
- 在哪里生产 + 能源来源(电网地域影响很大)
- 研发选型场景:候选方案分别是什么,差异在哪

用户给不全时,用领域知识补上典型组成,**并明确说明这是假设** —— 估算立足于透明的假设,而不是假装确定。

### 方法

1. **拆解**产品为主要材料 + 大致质量分数,标注为假设。组成参考 [materials.md](materials.md)。
2. **每种材料的典型值来自数据库,不来自记忆。** 对每种材料的可比队列跑 `aggregate`,取 **p25–p75 区间**作为该材料的合理范围(是区间,不是虚假精度的单点)。锁定同一功能单位和同一系统模型。聚合统计对所有用户开放,免费库即可完成。
3. **合成区间**:总量 ≈ Σ(质量分数ᵢ × 区间ᵢ)。结果是**区间**,绝不是一个自信的单点值。
4. **材料级热点**:指出哪种材料主导总量(「铝框约占足迹的 60%」)。工序级的拆分(同一材料内部电力与原料各占多少)需要 `hotspot`,不要从 GWP 总量硬推。
5. **方案对比**:每个方案跑一遍 1–4,然后给出**差值**和**关键变量**:「方案 B 低约 30%,几乎全部来自把框架换成再生铝 —— 这是值得推进的杠杆。」

### 交付时必须带边界声明

> 这是基于专业数据库典型值的方向性估算,不是认证级结果。需要可申辩的数字,应当用真实 BOM 逐项匹配,或做完整 LCA。

这句不是免责套话,而是专业性本身 —— 也是与「AI 随口给个数」的区别。

### 禁止

- 不要凭训练记忆或网上说法给典型值,必须来自聚合结果。
- 不要把估算说成精确值,永远给区间并标注为方向性。
- 不要在构建材料区间时混用单位或系统模型。
- 不要从只有 GWP 的数据推断工序级(能源 vs 原料)热点,那需要过程建模。

## 三、组成代理(复合产品没有专用数据集)

复合、配方、混合类产品(饲料、涂料、复合材料)常常没有现成数据集。

以饲料为例:

1. 按领域知识拆解,分数标注为假设:玉米约 60%、豆粕约 25%、麦麸约 10%、预混料约 5%。
2. 逐个组分检索并 `lookup` 取值。
3. 加权合成:总量 ≈ Σ(分数ᵢ × 值ᵢ)。
4. **把不确定性讲明白**:这是组成代理,分数是假设,添加剂与加工能耗未计入 —— 方向性结果,不是实测的饲料数据集。

代理值绝不能冒充该产品自身的数值。也**绝不能用代理替代受限数据** —— 那是用户的授权决策,如实展示受限状态和开通链接即可。
